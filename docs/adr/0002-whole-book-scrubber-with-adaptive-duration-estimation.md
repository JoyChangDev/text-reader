# Whole-book progress scrubber with adaptive duration estimation

Each Book's audio is generated one Chunk at a time, and most Chunks haven't been synthesized yet when a Book is opened — so their real duration is unknown up front. Rather than scoping the redesign's progress scrubber to just the current Chunk (which would sidestep the problem), we chose a whole-book scrubber: total duration is estimated per-Chunk from character count, using a `duration / characterCount` ratio observed from already-generated Chunks for the current voice (falling back to a rough default before any Chunk exists). Each estimate is replaced by the real duration the moment its Chunk is actually generated, so the scrubber's total length self-corrects over a session rather than committing to a one-time guess. The scrubber visually distinguishes generated (exact) segments from estimated segments so seeking into "unknown" territory — which triggers that Chunk's generation immediately, per ticket 1's existing seek behavior — isn't a silent surprise.

Considered alternative: scope the scrubber to the current Chunk only, with separate chunk-navigation controls. Rejected — it doesn't deliver the "real progress scrubber" the spec calls for, since it wouldn't show where you are in the book as a whole.
