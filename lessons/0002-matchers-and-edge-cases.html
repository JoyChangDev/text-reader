Lesson 0002 · New Matchers

讀一份真正的測試檔，學會 toBe 以外的 Matcher

目標：看懂 ticket 03（中文斷句 chunking 函式）已經幫你寫好的測試檔， 學會 toEqual、toMatch、數字邊界 matcher，然後親手替它補上一個還沒被涵蓋的邊界案例。

主要參考資料：Vitest — expect API 文件（官方文件）。 這篇列出所有 matcher；今天只挑 chunkText.test.js 裡實際用到的那幾個講。

先複習：AAA 沒變，變的是 Assert 那一步

Lesson 0001 學過 Arrange-Act-Assert，也用過 toBe 和 toHaveLength。今天的重點是：toBe 只適合數字、字串、布林這種「原始值」， 一旦要斷言陣列或物件，toBe 會出問題 —— 這是幾乎每個測試新手都會踩到的坑。

踩一次這個坑

假設你想斷言一個函式回傳空陣列，直覺會寫：

expect(chunkText('')).toBe([]);  // ❌ 這會失敗！

這會失敗，即使兩邊「看起來一樣」。原因是 toBe 用 Object.is（本質上是 ===）比較， 對陣列和物件來說，這是在問「是不是記憶體裡同一個東西」，不是「內容看起來是不是一樣」。 兩個獨立建立的空陣列，內容相同但不是同一個東西，所以 toBe 會說不相等。

正確寫法是用 toEqual，它做「深層比較」（deep equality）—— 逐一比對內容，不管是不是同一個記憶體位置：

expect(chunkText('')).toEqual([]);  // ✅ 比較內容，不是記憶體位置

經驗法則：數字、字串、布林用 toBe；陣列、物件用 toEqual。 不確定的時候，先猜 toEqual，通常不會錯。

讀真正的測試檔：chunkText.test.js

chunkText.js 是 ticket 03 的成果 —— 把一段中文段落切成一個個「唸起來剛好」的段落， 依照句尾標點（。！？）斷句，每個 chunk 大約 2–4 句、不超過字數上限。 chunkText.test.js 已經幫它寫好測試了。挑三個代表性案例來看： 

// 陣列的深層比較
test('returns a single chunk for text shorter than one full chunk', () => {
  const text = '你好。';
  const chunks = chunkText(text);
  expect(chunks).toEqual(['你好。']);  // toEqual，不是 toBe
});

// 用正規表達式比對「格式對不對」
test('splits a paragraph into chunks that each end on a sentence boundary', () => {
  const chunks = chunkText(text);
  for (const chunk of chunks) {
    expect(chunk).toMatch(/[。！？]$/);  // 每個 chunk 必須以句尾標點結束
  }
});

// 數字邊界
test('no chunk exceeds the configured maximum character count', () => {
  const chunks = chunkText(text, { maxChars: 20 });
  for (const chunk of chunks) {
    expect(chunk.length).toBeLessThanOrEqual(20);  // 小於等於，不是完全等於
  }
});
toEqual(value)深層比較內容 —— 陣列、物件都用這個
toMatch(regex)字串符合某個正規表達式（格式對不對）
toBeGreaterThan(n)數字大於 n
toBeLessThanOrEqual(n)數字小於等於 n（上限用這個，不是 toBe）

注意每個測試案例的名字都直接對應 ticket 03 的驗收清單 （例如「no chunk exceeds the configured maximum character count」就是清單上的第二項）。 這是個好習慣：測試名稱就是需求清單的翻譯。

動手做 · 今天的目標

ticket 03 的驗收清單全部打勾了，但有一個輸入從來沒被測過：空字串。 chunkText('') 應該回傳什麼？追一下 chunkText.js 的邏輯： 沒有任何句子可以切，所以應該回傳一個空陣列 []。

步驟：

  1. 開一個監看視窗：npm run test:watch。
  2. 打開 chunkText.test.js，在 describe('chunkText', ...) 區塊裡新增一個測試案例， 名字取類似 'returns an empty array for empty input'。
  3. 照 AAA 寫：Arrange 一個空字串、Act 呼叫 chunkText、Assert 用今天學到的正確 matcher斷言結果是空陣列。
  4. 存檔確認測試變綠。想一下：如果你手滑寫成 toBe([]) 會發生什麼事？可以先故意寫錯，看一次失敗訊息，再改回來 —— 這是很有用的直覺養成。

這個測試會留在專案裡，跟其他七個案例一起保護 chunkText 未來不被改壞 —— 這不是丟掉的練習題。
