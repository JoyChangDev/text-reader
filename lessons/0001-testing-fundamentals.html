Lesson 0001 · Testing Fundamentals

你的第一個測試：斷言與 Arrange-Act-Assert

目標：看懂一個測試在做什麼、學會 AAA 這個思考框架，然後親手為 text-reader 寫下你的第一個測試案例。

主要參考資料：Vitest — Getting Started Guide（官方文件）。 這篇教你怎麼安裝、設定、跑 Vitest；今天這堂課只挑你現在需要的那一小部分講。

什麼是「測試」？

一個測試，就是一段會自動檢查你的程式碼行為是否符合預期的程式碼。 你寫一段輸入，跑你要測的程式碼，然後斷言（assert）結果應該長什麼樣子。 如果結果不符，測試框架會讓那個測試「變紅」，並告訴你哪裡不符合預期 — 這比自己手動在瀏覽器裡點來點去檢查快非常多，而且以後改 code 時還能重複執行。

解剖一個測試：Arrange, Act, Assert

幾乎所有的單元測試，都可以拆成三個步驟，簡稱 AAA：

  • Arrange（準備） — 準備測試需要的輸入、初始狀態。
  • Act（執行） — 呼叫你真正要測試的那個函式或行為，通常只有一行。
  • Assert（斷言） — 用 expect(...) 斷言結果是你預期的樣子。

這個框架的價值在於：當你不知道怎麼下手寫一個測試時，先問自己「我的 Arrange 是什麼？Act 是什麼？Assert 是什麼？」， 三個問題想清楚了，測試也就寫完了。

讀懂專案裡現有的測試

這個專案已經有一個測試檔了： app/page.test.jsx。用 AAA 拆開來看： 

test('renders the home page buttons', () => {
  // Arrange + Act：把元件渲染到一個虛擬 DOM 裡
  render(
    <ChakraProvider>
      <Home />
    </ChakraProvider>,
  );

  // Assert：斷言畫面上有兩個名為「Click me」的按鈕
  expect(screen.getAllByRole('button', { name: 'Click me' })).toHaveLength(2);
});

注意 getAllByRole('button', { name: 'Click me' }) 這個查詢方式 — 它是在問「一個使用者會怎麼在畫面上找到這個按鈕？」而不是去戳元件內部的 state 或 props。 這是 Testing Library 的核心精神： 「你的測試越像使用者實際使用軟體的方式，它就能給你越多信心。」 下一堂課會更深入這一塊；今天先记住這個查詢方式存在就好。

動手做 · 今天的目標

幫 text-reader 寫一個之後播放器會用到的小工具函式： formatDuration(totalSeconds) — 把秒數轉成 "mm:ss" 格式的字串 （例如 65 秒 → "01:05"），用來顯示播放進度。

兩個檔案已經幫你建好骨架：

  • app/_lib/formatDuration.js — 函式本體是空的，等你實作。
  • app/_lib/formatDuration.test.js — 已經有一個完整的 AAA 範例測試（0 秒 → "00:00"），還留了兩個 TODO 給你自己寫。

步驟：

  1. 先在終端機開一個監看視窗：npm run test:watch（改檔案存檔就會自動重跑，馬上看到紅/綠）。
  2. 照著 formatDuration.test.js 裡第一個測試的 AAA 寫法，把兩個 TODO 換成真正的 test(...)：
    • 5 秒 → "00:05"
    • 65 秒 → "01:05"
  3. 這時候測試應該是紅的（因為 formatDuration 還沒實作）— 這是預期的，繼續下一步。
  4. 回到 formatDuration.js，把函式寫完，讓三個測試都變綠。

這個練習範圍刻意縮小：不用處理超過一小時的情況（沒有 hh: 前綴），也不用處理負數。 先把 AAA 寫熟，之後真正要用在播放器上時再擴充。
